What we asked DL-Learner to learn, and how we tested it

Target and examples

P = eastbound trains (Michie: “OK”), N = the rest. Balanced: 5/5, 12/12, 100/100.

No leakage

The label is never asserted in the ontology. It appears only in the example lists of each .conf file.

Splits

Leave-one-out for 10 and 24 trains, stratified 5-fold for 200. The baselines use the same folds.

Hypothesis language

ALC(D) with ⊓ ⊔ ¬ ∃ ∀, ≥n / ≤n and ∃d.[range]. Length: atom = 1, ∃r.C = 2 + |C|.

Test evaluation: we take DL-Learner’s best concept and classify the held-out trains with our own closed-world evaluator, which reproduces DL-Learner’s training accuracies exactly.

Team 6 · Concept Induction on Michalski’s Trains

Step three of the brief: the learning problem. Positives are the eastbound trains, or the OK trains for Michie's set; negatives are the rest, and all sets are balanced. To avoid leakage, the label is never written into the ontology; it only appears in the example lists of the configuration files. For the small real sets we use leave-one-out, and for the synthetic sets stratified five-fold cross-validation, with exactly the same folds for the baselines. The hypothesis language is ALC with numeric data restrictions and number restrictions. Because DL-Learner only reports training accuracy, we classify the held-out trains ourselves with an evaluator that uses the same closed-world semantics as DL-Learner's reasoner.
